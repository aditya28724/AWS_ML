Business Entity Resolution: design

Two stages: candidate blocking, then a gradient-boosted pairwise matcher, followed by precision-first decision logic.

2. End-to-end algorithm

flowchart TD
  A[Load S1, S2, S3 .tsv] --> B[Normalize: lowercase, strip accents,
expand abbreviations, split legal suffix,
extract numbers and postcodes]
  B --> C{{Blocking: union of candidates}}
  C --> C1[TF-IDF char 3-5 gram
name + address, top-K]
  C --> C2[Multilingual embedding
kNN top-K]
  C --> C3[Shared rare token
or postcode]
  C1 & C2 & C3 --> D[Candidate pairs S1 x S2/S3
written to candidate_pairs.tsv]
  D --> E[Pair features: Jaro-Winkler, Levenshtein,
token-set ratio, TF-IDF and embedding cosine,
number overlap, rarity-weighted Jaccard,
blocking rank, missing flags]
  E --> F{Train or test?}
  F -- train --> G[Label pairs from ground truth]
  G --> H[LightGBM, GroupKFold by S1 id]
  H --> I[Out-of-fold probs: tune threshold
for macro F0.5, check blocking recall]
  I --> J[(Saved model + threshold)]
  F -- test --> K[Score pairs with saved model]
  J -.-> K
  K --> L[Decision resolver]
  L --> M[matching_results.tsv
one row per S1, empty if singleton]
  M --> N[Run validate_submission.py]

3. Decision logic (precision-first)

flowchart TD
  S[Scored pairs] --> T[Each S2/S3 record keeps only its
best-scoring S1: S1 is deduplicated,
so one record maps to one entity]
  T --> U{"p ≥ threshold?"}
  U -- no --> X[Drop pair]
  U -- yes --> V{"p ≥ best p for this S1 − margin?"}
  V -- no --> X
  V -- yes --> W[Keep match]
  W --> Y[Group matches by S1]
  X --> Y
  Y --> Z{Any matches?}
  Z -- yes --> Z1[Write ID list]
  Z -- no --> Z2[Write empty list: singleton scores 1.0]
